# 90-Second Pitch Script — Quantum Feature Mapping Lab

A tight, live-demo script for showing this in ~90 seconds — an elevator pitch with the screen as the visual aid, not a recorded video. English and Spanish versions below cover the same beats at the same pace; use whichever fits the room. All numbers are real, unmodified results from the Kipu Quantum Hub benchmark run.

**Before you start:** have the app open at the landing view, and know the click path for §3 (Live Board → Simulate perillas → "Quantum catches it (Classical misses)") cold — there's no time to hunt for it live.

---

## English

**[0:00–0:08] Open**
**[SCREEN]** Landing view.
> "This is a live demo, no login. It predicts when a hoist cable is about to rupture, before it happens. Here's the key: we don't replace your ML model — we enrich the data that feeds it."

**[0:08–0:20] One number**
**[SCREEN]** Point at the KPI card / bar comparison.
> "Same sensors, richer representation: precision on real ruptures nearly doubles — from 34 to 68 percent. Same model, same training. Only the data changed."

**[0:20–1:10] The moment that matters**
**[SCREEN]** Open **📡 Live Board** → **🎚️ Simulate perillas** → click **"Quantum catches it (Classical misses)"**.
> "Let me show you why. This is a real recorded case — a real rupture. Right now the switch is on Classical: the model looks at these exact numbers and says everything's fine. Same numbers, same machine — flip it to Quantum..." **[SCREEN]** flip the switch. **"...and it catches it.** Same data. Same kind of model. The only thing that changed is what the model was given to see."

**[1:10–1:30] Close**
> "That's the whole idea: we don't touch your pipeline, we transform what feeds it. This is live right now at quantum-feature-mappping-lab.vercel.app — try it yourself."

*(~230 words. If you're running long, cut nothing from the Live Board moment — trim the opening line instead.)*

## Notes for either language

- The Live Board moment is the entire point of doing this live instead of just showing a screenshot — never cut it short to save time elsewhere.
- If asked a question mid-pitch, answer briefly and land on the close line ("we transform the data, not your model") — don't get pulled into the metrics glossary at this length; that's what `demo-guide.md` / `demo-guide-es.md` are for.
- Rehearse the exact click path before presenting — verify against the current build, not from memory.
